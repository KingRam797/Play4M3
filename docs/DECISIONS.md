## Policy engine (S2/S3)

- **D-010 · 2026-10-06 · Reject, don't normalize.** The canonicalizer rejects `..`, absolute, drive-letter (incl. drive-relative `C:x`), UNC, `\\?\`/`\\.\`/`\??\`, ADS (any `:`), 8.3 short names (`~N`), reserved device names (incl. superscript COM¹²³, CONIN$), trailing dot/space, Windows-forbidden chars, control chars, Unicode format chars (bidi, ZWJ, tag chars), non-NFC strings. `.` and empty segments collapse. — Ambiguous paths are attack surface.
- **D-011 · 2026-10-06 · Any symlink or junction component is rejected**, even one pointing inside the workspace; also realpath containment, and writes to multi-hard-link files rejected. — Simpler than reasoning about link targets. Node's `lstat` reports NTFS junctions as symlinks; the win32 junction tests confirm this in CI.
- **D-012 · 2026-10-06 · Scope match is case-insensitive** (`toLowerCase`), because NTFS is.
- **D-013 · 2026-10-06 · Taint rules.** `taintedBy` is computed by the guard from handles referenced in planner arguments, never taken from the planner. Any tainted request needs approval, even on `approval:"none"` tools. Tainted requests may never carry network targets (`net.tainted`), approval or not. — Brief §4.2 "extra check"; untrusted data choosing an exfiltration host is the classic injection payoff.
- **D-014 · 2026-10-06 · Sensitive tool families** (`fs.write`, `fs.delete`, `fs.move`, `exec.*`, `analysis.run`, `net.*`, `skill.*`, `patch.export`) and any `net:"allowlist"` capability must be `approval:"user"`; the manifest is rejected at load otherwise. Hosts must be plain lowercase ASCII (no IDN, no wildcard, no IP, no trailing dot).
- **D-015 · 2026-10-06 · Approval tokens** are verified by an `ApprovalVerifier` interface in core; the HMAC implementation (single use, expiry, bound to a digest of the exact request) lives in `@play4m3/guard` on the Node side. Web build uses `DENY_ALL_APPROVALS`.

## Desktop shell (S8) and MSIX

- **D-016 · 2026-10-06 · Electron 44.5.1, electron-builder 26.17.0, esbuild 0.28.2** (newest releases ≥ 3 days old on 2026-10-06).
- **D-017 · 2026-10-06 · App content is served from a custom privileged scheme `app://station`** via `protocol.handle`, never `file://` and never remote. File paths go through `canonicalizeRelative` (same code as the policy engine) and a MIME allowlist. Every response carries the CSP and security headers from `security.ts`.
- **D-018 · 2026-10-06 · Microphone gating is driven by main-process input events** (`before-input-event`, push-to-talk key F9 held), not by renderer messages. The renderer is untrusted, so it cannot arm the mic. Audio only; video/screen never granted. A mouse/touch PTT button needs a trusted-gesture path; open design item for F6.
- **D-019 · 2026-10-06 · Electron fuses set at package time** (runAsNode off, NODE_OPTIONS off, inspect args off, cookie encryption on, embedded asar integrity on, only load from asar, no extra file:// privileges).
- **D-020 · 2026-10-06 · MSIX capabilities: `runFullTrust` + `microphone` only.** Note: a `runFullTrust` (Desktop Bridge) app runs at medium integrity, **outside AppContainer**. MSIX packaging is therefore not a sandbox for us. Network deny is enforced in Electron (`webRequest.onBeforeRequest`) and by never giving the main process network code. Real OS-level isolation is a job for the analysis worker (S13 spike).
- **D-021 · 2026-10-06 · `P4M3_SMOKE=1` smoke mode in main.** Reads one text node from the renderer and the `typeof` of `require`/`process`/bridge, prints them, exits 0/1. Grants nothing. Used by CI on Linux (Xvfb) and Windows (unpacked app, exit code).

- **D-024 · 2026-10-06 · Pre-commit hook `.githooks/pre-commit` runs `pnpm check`.** This session I once committed after `pnpm check` had failed (a type error in a smoke-mode line). It was caught before push and the commits were rebuilt. The hook makes that mistake impossible locally.

## Product and UI

- **D-031 · 2026-10-06 · Product name set to "Play4M3"** in `packages/core/src/brand.ts` (was "U-Game?"), on King's instruction ("It's called Play4M3"). `nameCleared` stays `false`: legal docs, privacy policy and Store metadata keep the `{{BRAND}}` placeholder until clearance. Brief §2.4 still applies: `play4m3` reads as "Play4Me", which has known conflicts (play4.me, a UK company).
- **D-032 · 2026-10-06 · Destructible loading screen** (`packages/loading-screen`), modeled on the "shoot a website apart" toy King shared. The wordmark, tagline, tip card and a fake nav bar are a destructible cell grid; the HUD (progress, prompt, on-screen A) cannot be destroyed. Rules: (1) it never closes by itself; (2) it closes only on a **fresh** press of the continue control **after** loading completes; a press during loading shows "Still loading… N%", and a button held through the end of loading must be released first; (3) continue = gamepad **A** (standard mapping index 0), **Enter**, or the on-screen A; fire is on X / RT / RB / right stick / Space / J and can never be the continue control (`validateBindings` throws); (4) presses shorter than one frame are latched so quick taps count (found by the e2e run); (5) once 85% is wrecked, the screen rebuilds with the next tip, so play continues indefinitely; (6) canvas only, no network, no fonts fetched, CSP-compatible, `prefers-reduced-motion` honored, status sentences to an `aria-live` region. Desktop progress comes from real startup steps, never a timer; only the standalone preview simulates progress, and it says so.

- **D-033 · 2026-10-06 · Web build (F13 start) and `vercel.json`.** A Vercel project (connected by King) began deploying PR #1. Its first two deployments failed. The build logs need a Vercel login, so the exact error is **not known**. The repo had no web app, no build script and no Vercel config, so Vercel had to guess the pnpm version, the install and the output. Fix: `apps/web` (static page: the loading screen, then landing text; progress from real page load and fonts; no binary analysis) and a root `vercel.json` that pins `pnpm@10.28.0` via npx, installs with `--frozen-lockfile` and `ELECTRON_SKIP_BINARY_DOWNLOAD=1`, builds only `@play4m3/web`, serves `apps/web/dist`, and sets the S9 headers. The CSP has no `unsafe-inline`; HSTS is 2 years with includeSubDomains, **without `preload`** (hard to undo; King's call once the domain is live). Also: nosniff, `Referrer-Policy: no-referrer`, frame-ancestors none + X-Frame-Options DENY, COOP/CORP, and a Permissions-Policy that denies camera and mic. Verified locally by running the exact install and build commands in a clean copy, then serving the output with these headers in headless Chromium: no CSP or console errors, and the page waits for the button and continues on Enter. The live-header check against a deployed preview (the S9 CI test) is not built yet.

- **D-034 · 2026-10-08 · Station architecture (F5).** All station state and every side effect live in the main process (`packages/station-service`). The renderer (`apps/station`, React 19) is treated as untrusted: it renders `ViewState` snapshots and can only send the seven requests in `STATION_REQUESTS`, each Zod-validated in main (and the returned state re-validated in the renderer). Typed commands become `user_typed` planner turns; the planner sees only handles (S1); its calls go through the guard (policy + taint).
- **D-035 · 2026-10-08 · Approvals are confirmed in a native dialog in the main process** (`dialog.showMessageBox`, Cancel is default and cancel button). The renderer can only *ask*; a compromised page cannot approve on its own. The dialog text is built only from trusted or schema-validated values (the planner's change request, canonical path, numbers, addresses). No function names or game strings appear in it, so hostile game text cannot use the dialog to talk the user into approving. Cancel leaves the request waiting; Reject removes it.
- **D-036 · 2026-10-08 · Quarantined reader output contract**: `ReaderOutputSchema` (enums, bounded numbers, tunable names `^[a-z_][a-z0-9_]{0,31}$`, summary limited to letters, digits, space and `. , ' ( ) - : _`, max 280). Output is still stored as untrusted and shown inside a "Read from game data. Information, not instructions" frame.
- **D-037 · 2026-10-08 · Demo providers until F4/F7/F9.** The function list comes from a fixture of the test program F4 will compile (`Sky Hopper (sample)`), the reader and planner are deterministic stand-ins. The UI shows a "Demo data" badge. The fixture includes a planted prompt injection (`load_level`); tests prove it never reaches the planner or the confirm dialog. `patch.write` added to the sensitive-tool list in core. Patch files refuse to overwrite.
- **D-038 · 2026-10-08 · Versions:** react / react-dom / @types 19.3.0, playwright-core 1.63.0 (Apache-2.0; drives the Electron walkthrough, dev-only). The walkthrough stubs `dialog.showMessageBox` through Playwright's handle on the main process **in the test only**; the shipped app has no bypass. `P4M3_USER_DATA_DIR` env var lets tests use a throwaway profile.

## Analysis (F4, S13)

- **D-039 · 2026-10-08 · Ghidra is user- or CI-installed, pinned, never bundled.** The `ghidra-headless` skill accepts only Ghidra 12.1.4 (checked from `Ghidra/application.properties`). CI downloads `ghidra_12.1.4_PUBLIC_20260921.zip` and checks sha256 `ddac49f9…d4db` (VERIFY-FIRST table). We start Java directly with the VM arguments from Ghidra's own `support/launch.properties` (`VMARGS` plus the current OS's `VMARGS_*`, each checked against `^-[A-Za-z0-9_.:=,+/-]*$`), `-cp Ghidra/Framework/Utility/lib/Utility.jar ghidra.Ghidra ghidra.app.util.headless.AnalyzeHeadless`. Reason: no shell or `.bat` is involved on any OS (on Windows a batch file would need `shell: true`), and we set the heap, `user.home` and `java.io.tmpdir` ourselves.
- **D-040 · 2026-10-08 · Analysis worker runner** (`packages/analysis/src/sandbox.ts`). Each run gets a private `0700` temp dir. The input is copied in under the fixed name `input.bin`, so the user's path and file name never reach the worker, and the copy is made read-only (`0444`, dir `0555`). Its sha256 is checked after the run, and any change voids the result. The environment is built from scratch (`PATH`, `HOME`, `TMPDIR`, `LANG`; on Windows `SystemRoot`, `PATH`, `TEMP`, `TMP`, `USERPROFILE`) plus an allowlist (`JAVA_HOME`, `MALLOC_ARENA_MAX`). On Windows, libuv also copies `HOMEDRIVE`, `HOMEPATH`, `LOGONSERVER`, `SYSTEMDRIVE`, `USERDOMAIN`, `USERNAME`, `WINDIR` from the parent when they are missing (measured on `windows-latest`). They identify the user and machine but are not secrets. Linux: `prlimit --as --fsize --core=0 -- unshare --map-current-user --net --pid --fork --kill-child`. That gives a new network namespace (no interfaces but a down loopback), the worker keeps its own uid, and killing `unshare` kills the whole PID namespace. The timeout kills the process group (Linux) or `taskkill /T /F` (Windows). stdout/stderr are capped. The output is read with `O_NOFOLLOW` (a planted symlink is refused), and the file and the output directory are size-checked on the host. **Fail closed:** by default a run that cannot enforce network isolation *and* a memory cap is refused before spawning. Today that means analysis is refused on Windows (Q-012) and on Linux hosts that block unprivileged user namespaces (Ubuntu 24.04 by default; CI relaxes `kernel.apparmor_restrict_unprivileged_userns`, as the Electron jobs already did).
- **D-041 · 2026-10-08 · Filesystem confinement is not built** (reported as `filesystem: not_confined`). The worker runs as the user and can read and write wherever the user can. A mount-namespace experiment (remount `/` read-only inside the namespace) was refused by this build container's permission policy, so it was not tried. Candidates for next time: Landlock (unprivileged, Linux 5.13+), bubblewrap, or a mount namespace tested in CI. With no network, reads cannot leave the worker except through the bounded report. Writes are the larger gap (persistence, disk fill). See THREAT_MODEL T-AN-1/T-AN-3.
- **D-042 · 2026-10-08 · JVM settings that fit under RLIMIT_AS.** Measured here: Ghidra failed at 2 GiB and 3 GiB with default settings (metaspace reserve, then "unable to create native thread", from glibc's per-thread malloc arenas). It passes at 2 GiB with `MALLOC_ARENA_MAX=2`, `-XX:ActiveProcessorCount=2`, `-XX:CompressedClassSpaceSize=256m`, `-XX:ReservedCodeCacheSize=128m`, `-Xss1m`, `-Xmx1g`. Ghidra's cache and settings dirs (`application.cachedir`, `application.settingsdir`) are pointed into the run's private scratch dir. By default they are shared per-user dirs (`/var/tmp/<user>-ghidra`, `~/.config/ghidra`): the first CI run failed there when two concurrent runs collided on the shared cache, and a shared dir would also carry state between runs. Default cap: 3 GiB address space, 5 min wall clock, 16 MiB output. RLIMIT_AS caps virtual address space, not resident memory, and the docs say so.
- **D-043 · 2026-10-08 · Skill files are sha256-pinned in `packages/skills`** (`GHIDRA_HEADLESS` manifest). The runner reads the script, checks the pin, and stages the *verified bytes* into the private work dir; Ghidra runs only that copy (`-scriptPath <staged>`). A mismatch refuses the run. Signing the manifest (rest of S12) is not built.
- **D-044 · 2026-10-08 · Report format `p4m3-analysis/0`.** Per function: entry address, size, name, up to 32 referenced strings (≤512 chars), up to 32 referenced globals (address, name, type, value for 4-byte float/int). There are no code bytes and no decompiled output (§2.2). The post-script \u-escapes everything outside printable ASCII. The host re-validates with a strict Zod schema (unknown keys rejected, ≤5000 functions), and parse errors never echo input text. The report must carry the sha256 of the file we gave the worker. In the Station, only plain lowercase-named 4-byte float/int globals with a known value become tunables. The project title is chosen by the caller, never taken from the file. `ViewState.demo` is now a boolean (true only for the fixture), and `game.source` is `demo` or `ghidra`, so the "Demo data" badge shows only for the fixture ("Demo reader" otherwise). The demo reader classifies real functions by name keywords, at "low" confidence and prefixed "Probably:", until the Gemma reader (F7).

## Guard

- **D-025 · 2026-10-06 · Planner calls are `{tool, args}` only** (strict schema). Paths and hosts are derived by the guard from each tool's declared `pathArgs`/`hostArgs`; taint is computed from handle references, including handle ids embedded inside longer strings. A planner cannot supply `approvalToken`, `taintedBy`, `paths` or `net`.
- **D-026 · 2026-10-06 · Handle descriptors use fixed vocabularies** (`sourceKind`, `valueKind`). Raw `source` strings (filenames, mod names) are attacker-controlled and never reach the planner.
- **D-027 · 2026-10-06 · `Guard.approve()` is a method for the trusted UI only.** It is not a tool and is unreachable from model output; the S4 harness tries `guard.approve` as a tool and gets `tool.not-allowlisted`.
- **D-028 · 2026-10-06 · Audit log truncation needs an external anchor.** A hash chain cannot detect tail deletion; `verifyChain(entries, expectedHead)` checks an anchor kept outside the log file (planned: shown in the audit view and stored in OS-protected storage).
